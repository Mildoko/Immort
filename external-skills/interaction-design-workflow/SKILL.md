# 交互设计工作流

## When to Use

为产品做交互设计/UI 设计时，尤其是：
- 需要产出「界面提示词」（用于 AI 生成界面或给设计师）
- 需要为多界面产品做信息架构与导航整合
- 发现界面「孤岛」（做了界面但没定义入口/跳转）

## 核心工作流（6 步）

```
① 系统拆分 → ② 定规范 → ③ 写界面(含入口/出口) → ④ 理架构 → ⑤ 校验导航闭环 → ⑥ 补缺口
```

| 步 | 产出 | 要点 |
| :--- | :--- | :--- |
| ① 系统拆分 | 策划案 + 交互案 | 交互案含页面流/操作矩阵 |
| ② 定规范 | UI 设计规范 | **先定规范，再做界面** |
| ③ 写界面 | 界面提示词 | **做界面时同步定义入口/出口**，含概述 + 完整结构 + 生成提示词 |
| ④ 理架构 | 信息架构 | 分层：Tab主页/下级页/流程页/组件 |
| ⑤ 校验导航闭环 | 完整导航地图 | 从主界面按钮串所有子界面 + 可达性检查（校验③是否闭环） |
| ⑥ 补缺口 | 补齐界面/入口 | 消除孤儿界面、补缺失入口 |

## 关键原则

1. **先定规范，再做界面** —— 先出 UI 设计规范（画布/色彩/字体/标题/按钮/全屏/二级界面/弹窗/图标），界面引用规范；新元素**回补规范**。
2. **界面 = 界面提示词 + 交互规则说明** —— 提示词讲「长什么样」，规则讲「页面流/操作矩阵/异常」。
3. **做界面时就定义上游和下游（入口/出口都明确）** —— 做**每个界面**时，同步定义它的**上游**（从哪进/哪个界面的哪个按钮）和**下游**（每个按钮点到哪去）。导航不是「事后补」，而是「做界面时同步定义」；整体信息架构 + 可达性检查作为**收尾校验**（不是替代）。
   - 反面教训：先做完 46 个界面，才发现全是「孤岛」。
4. **分清入口页 vs 详情页** —— 能从底部导航直达的 = Tab 主页；要从入口点进的 = 下级页。**不要**把入口页和详情页做成平级。
5. **从主界面按钮出发串子界面** —— 逐按钮追踪到所有子界面。
6. **可达性检查** —— 每个界面确认「从哪可达」，消灭孤儿界面与缺失入口。

## UI 设计规范（核心）

> 完整规范见 `references/ui-design-spec.md`。

### 画布
1080×1920（9:16），8pt 栅格，页边距 32，@2x/@3x。

### 色彩
品牌活力橙 `#FF6B35` / 辅助城市蓝 `#2D7FF9` / 功能色（成功 #22C55E、警告 #F59E0B、危险 #EF4444）/ 中性色。

### 排版体系（8 级，1080 基准）

| 层级 | 字号 | 字重 | 行高 | 颜色 | 场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Display | 64 | Bold | 1.2 | 主文字 | 数据大数字 |
| H1 | 40 | Bold | 1.3 | 主文字 | 页面标题（导航栏） |
| H2 | 34 | Semibold | 1.35 | 主文字 | 区块标题 |
| H3 | 30 | Semibold | 1.4 | 主文字 | 卡片/列表标题 |
| Body-L | 28 | Regular | 1.5 | 主文字 | 正文（重点） |
| Body | 26 | Regular | 1.5 | 主文字 | 常规正文 |
| Caption | 24 | Regular | 1.4 | 次文字 | 辅助说明 |
| Footnote | 20 | Regular | 1.4 | 弱文字 | 注脚/时间戳 |

**文字颜色**：主 `#1A1A1A` / 次 `#666666` / 弱 `#999999` / 反白 `#FFFFFF` / 品牌强调 `#FF6B35`。
**排版规则**：行高（标题 1.2-1.4、正文 1.5）、字间距（大标题 -0.5px）、段落间距（24/32）、数据用等宽数字。

### 关键组件
- **标题**：H1 页面 / H2 区块 / H3 卡片 / Display 数据。
- **按钮**：主（活力橙高 88）/ 次（白底灰边）/ 文字；圆角 16。
- **全屏**：标准（导航栏 88）/ 沉浸式 / Tab 页（底部栏 100）。
- **二级界面**：导航栏 88 + 返回 + 内容边距 32 + 底部操作栏 120。
- **弹窗**：居中（宽 600）/ 底部 / Toast / 确认。
- **图标**：线性圆角 2px，48/40/32。
- **圆角**：卡片 24 / 按钮 16 / 小元素 8。

## 界面提示词标准格式

```
# <界面名> · 完整界面提示词
> 遵循《UI 设计规范》。系统：SYxx。

## 一、界面概述
| 类型 | Tab主页/二级页/组件/弹窗 |
| 目标 | 解决什么 |
| 入口（上游） | 从哪进（哪个界面的哪个按钮） |
| 出口（下游） | 每个按钮 → 目标界面 |

## 二、完整结构（自上而下）
① 导航栏 ② 内容区 ③ 底部操作

## 三、生成提示词
> 中文：微信小程序竖屏…（可直接复制）
> English: WeChat Mini Program vertical…（英文版）
```

> **入口/出口必须写**：做界面时就定义上游和下游，不留孤岛。

## 信息架构分层

| 层级 | 定义 | 例 |
| :--- | :--- | :--- |
| L0 Tab 主页面 | 底部导航直达 | 首页/消息/我的/发布 |
| L1 下级页 | Tab 内点入口 | 我的数据/搭子/斑币/任务 |
| L2 流程页 | 业务流程串联 | 详情→报名→支付→凭证 |
| 组件/弹窗 | 非独立页 | 洞察卡/评价摘要/城市选择 |

## 导航梳理步骤（收尾校验）

1. 逐个 Tab 列按钮 → 2. 每个按钮追目标 → 3. 画链路 → 4. 查可达 → 5. 补缺口
- 产出：按钮级追踪表 + Mermaid 流程图。

## 避坑清单

| 坑 | 避法 |
| :--- | :--- |
| 界面风格不一 | 先定规范 |
| 界面成孤岛 | **做界面时就写入口/出口**（不要事后补） |
| 入口页/详情页平级 | 判断层级 |
| 孤儿界面/缺失入口 | 可达性检查 |
| 重复界面 | 整合时去重 |
| 覆盖不全 | 从主界面按钮逐条串 |

## Checklist

- [ ] UI 设计规范已定（含标题/按钮/全屏/二级/弹窗/图标）
- [ ] 每界面有界面提示词（概述含**入口/出口** + 结构 + 生成提示词）
- [ ] 每界面有交互规则说明（页面流/操作矩阵/异常）
- [ ] 信息架构已分层
- [ ] 导航地图已画（按钮级）
- [ ] 每界面可达（无孤儿 + 无缺失入口）
- [ ] 无重复界面，新元素已回补规范
