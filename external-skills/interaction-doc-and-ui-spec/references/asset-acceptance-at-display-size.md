# 交付图验收实录：在「最终显示尺寸」下判断

配套 `interaction-doc-and-ui-spec` **§七**。本文是那套方法的**完整走查记录**，可当模板复用。

---

## 场景

- 用户拿来一张 AI 生成的**沙漠绿洲终态全景**（1672 × 941 ≈ 16:9，ChatGPT Image）
- 它是「终态先行」体系里的**母版**（见 `meta-game-build-families` §二.5）
- 它要供给两个用途：① 主界面**常驻场景区 = 882 × 260**（3.4:1）的取景框 ② 详情页完整全景
- 评审目标：**能不能定版**

**关键前提**：不能看原图拍板。它要活在一个 3.4:1 的扁条里，且是玩家每天看若干次的常驻元素。

---

## 检查一 · 缩到实际尺寸（三条带对照）

```python
from PIL import Image
im = Image.open(src).convert("RGB"); W, H = im.size      # 1672, 941
band = round(W * 260 / 882)                              # → 493
for name, off in [("top", 0), ("mid", (H-band)//2), ("bot", H-band)]:
    im.crop((0, off, W, off+band)).resize((882, 260), Image.LANCZOS).save(f"{name}.png")
# 再把三条竖排拼一张对照图，便于一次看全
```

### 结果（这一条检查的信息量最大）

| 取带 | 内容 | 判定 |
| --- | --- | --- |
| **上带** | 大片天空 + 浮空花园 + 远景山脊与城堡 | ❌ **像"奇幻大陆全景"，不像绿洲** —— 大面积被天空与山占掉 |
| **中带** | 神殿 + 瀑布群 + 湖水 + 棕榈 + 桥 | ✅ **最好** —— 水、绿、建筑三者齐备，一眼就是"繁盛绿洲" |
| **下带** | 夜景市集 + 骆驼商队 + 水池 | ⚠️ 人文感强，但帐篷顶部被裁断，**像"市集的一角"** |

### 结论（注意结论的形状）

**不是**"能裁 / 不能裁"，而是：

> **能裁出可辨认的画面，但必须为该比例单独构图** —— 焦点数量、元素体量、留白都要重定。**不能直接拿 16:9 全景裁。**

### 同时发现：细节全糊

缩到 260 px 高之后，**灯笼、织物纹样、货物、人物全部消失**。这说明该图的密度是**概念图级**，不是**常驻界面级** —— 而常驻元素密度过高会与同屏下方 126 px 的棋盘格**抢注意力**，且显得糊乱。

⇒ 这一条直接推翻"构图没问题就定版"的想法，产出了一条**降密**的修订要求。

## 检查二 · 2× 局部放大做风格审计

放大**画面最复杂的区域**（本例选了夜市帐篷与货物区 —— 细节最密处最能暴露技法），不放大看不出描边与光影。

### 审计结果

| 规范要求 | 成图实际 | 判定 |
| --- | --- | --- |
| 圆头圆角描边、线宽 6 px（与操作对象统一） | **完全没有描边线条**，全靠明暗塑造体积 | ❌ |
| 平涂 + 轻渐变；无写实光影 | 落日主光 + 大气透视 + 辉光 + 投影 + 环境光遮蔽 | ❌ |
| 统一轴侧 45°（平行投影） | 强透视，有明确消失点 | ❌ |
| 无 3D | 观感接近半写实数字绘景 | ⚠️ 边界 |
| 画面信息密度可控 | 极高（远山 + 多座建筑 + 瀑布群 + 多座浮空岛 + 人物） | ❌ |
| 无文字 | ✓ | ✅ |
| 色板锁定 | ✓（青蓝水体 / 沙金 / 铜金 / 深青都在约定范围内） | ✅ |

**关键认知**：AI 图的**默认审美就是"越满越写实越好"**，与"可执行、可复用"的界面规范天然对立。所以评审必须落到**可判定的硬指标**上，否则争论会停在"我觉得好看"。

---

## 做对的项（必须逐条列出并保留）

只列问题不列优点，下一版会把对的一起丢掉。

- **元素齐全度 100%** —— 设计里五个族（水 / 渠 / 绿 / 聚落 / 圣所）的元素**一个不缺**，连"水晶湖 + 石桥 + 浮空花园 + 市集骆驼 + 神殿发光宝石"都对上了
- **视觉焦点选得对** —— 把神殿里的发光宝石（= 元游戏的终极目标物）作为画面焦点，这个判断完全正确
- **文化语言准确** —— 拱门、穹顶、条纹帐篷、灯笼、织物纹样都在设定内
- **占比正确** —— 荒地只残留约两成，符合"繁盛终态"的设定
- **无文字** ✓
- **情绪对** —— 繁荣、水系发达、绿洲感强

## 检查三 · 可读性判据（本案例的核心结论）

同一次评审里要分清两类资产的**可读性要求不同**：

| 资产类别 | 最终显示尺寸 | 要求 |
| --- | --- | --- |
| **操作对象**（棋盘物品格） | **126 × 126 px** | **必须**描边 + 平涂 —— 否则"一眼分清 63 个格子里分别是什么"这条**玩法底线**破功 |
| **氛围画面**（场景横幅） | **882 × 260 px** | 可放松，允许天光与轻微大气感，但不要写实材质与强透视 |

⇒ 落点是**路径 A+**：**物品侧严守规范，场景侧放松**。两者的可读性要求本就不同，不必也不该用同一套风格强度。

> 写实光影 + 无描边放到 126 px 上只会糊成一团。**这是可读性问题，不是审美问题。**

## 产出 · 编号修订清单（退稿的标准格式）

不给形容词反馈。落成可直接拿去重出的编号项：

```
① 加描边   —— 全画面统一 6 px 圆头圆角 #33261A，与操作对象同一套线宽
② 改平涂   —— 去掉写实光影与大气透视，平涂 + 轻渐变（≤ 2 档明度）
③ 降透视   —— 改弱透视 / 近似轴侧，与游戏内物品视角靠拢
④ 大幅降密 —— 视觉焦点 ≤ 4 个（湖 / 神殿与目标物 / 浮空花园 / 市集）；
             删掉远景山脊城堡、多余瀑布、多余浮空岛；留出大面积渐变天空与地面
⑤ 保留     —— 五族元素齐全、目标物焦点、建筑语言、无文字、荒地只占边缘、暮色天空
⑥ 元素放大 —— 约 1.5×，确保缩到 882 × 260 后仍可辨认
```

---

## 附带产出 · 成图优于规范时要改规范

成图用的**紫橙暮色天空**比规范里定的「深蓝夜幕」好看得多，而且**提供了画面的暖光来源**。

**处理**：不改成图去迁就规范，而是**改规范去采纳**，并注明需相应补一组暮色天光色。规范是服务于结果的，不是反过来。

## 可复用清单（下次验收直接照跑）

1. **原图尺寸与实际显示尺寸分别是多少？** 比例差多少？
2. **缩到实际尺寸** → 出「上 / 中 / 下」三条带 → 哪条能认出目标场景？
3. **细节是否幸存？** 缩完糊掉 = 密度不匹配 = 不合格
4. **放大最复杂区域 2×** → 逐项过风格审计表（描边 / 光影 / 透视 / 密度 / 文字 / 色板）
5. **列出做对的项**（必须保留的）
6. **落成编号修订清单**（每条可执行、可点名到具体元素）
7. **成图有优于规范之处吗？** 有则改规范采纳
8. **资产类别判据对了吗？** 操作对象（小尺寸）宁要清晰，氛围画面（大尺寸）才谈氛围
