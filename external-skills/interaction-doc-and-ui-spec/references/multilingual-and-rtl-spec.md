# 多语产品 UI 规范：语言范围确认 + RTL 镜像方案

> 用途：写 UI/美术规范时，**先确认语言范围**，再决定排版与布局章节怎么写。
> 即使本版只做一种语言或只做 LTR，这份方案也应**存档待启**而不是丢弃 —— 产品一旦进中东/希伯来/南亚市场就会用到。
> 来源：中东女性向二合项目（Godot 4.x 原生竖屏 1080×1920）的规范推演。

## 一、先问的三个问题（写规范之前）

1. **本版支持几种语言？** 单语 / 双语同发 / 多语框架
2. **有没有 RTL（阿拉伯语、希伯来语）、竖排（日文）、超长语言（德/俄）？**
3. **界面语言与目标市场是否一致？** —— 不一致是很常见的坑：英文界面投中东市场，CPI 会因当地泛用户英语渗透率低而显著变高；反过来投泛英语市场则题材差异化失效。**两者的成功标准与买量素材完全不同，必须先分清验收目标。**

## 二、RTL 启用时要做四件事

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | **全局镜像开关** | 一个布尔 `is_rtl`（Godot 走 `TranslationServer` 的 locale），驱动所有 start/end 锚点翻转 |
| 2 | **字体打包** | **必须内置 Noto Sans Arabic 等字体文件**，不能依赖系统字体（Android 机型字体差异极大） |
| 3 | **字号/行高补偿** | 阿拉伯语字号 = 拉丁档位 **× 1.08 后取偶**；行高 **× 1.15**（连字与变音符号需更多垂直空间） |
| 4 | **文案长度复排** | 阿语通常比拉丁文案长 20–40%，**组件需按 1.5× 长度重新校验**；禁止在阿语词中间断行 |

> 第 1 件事的成本可以用一条零成本纪律**预付**：正文一律用 `start / end` 描述布局，永不写 `left / right`（见下方第三节）。

## 三、零成本预付：布局书写纪律

| 项 | 规范 |
| --- | --- |
| 锚点写法 | 一律 `start / end`，**即使本版不做 RTL** |
| 理由 | 不增加任何工作量；将来接 RTL 只需加一层镜像，**不必重画任何布局** |
| 反例 | 直接写 `left: 60px` 会变成隐藏债务 |

## 四、镜像判定表（哪些镜像、哪些绝对不镜像）

| 元素 | LTR→RTL 是否镜像 | 说明 |
| --- | --- | --- |
| 整体水平布局（板块左右顺序） | ✅ 镜像 | 由 start/end 锚点自动完成 |
| 文本对齐 | ✅ 镜像 | 一律 start 对齐 |
| 导航栏返回按钮 | ✅ 镜像 | 位置镜像，**箭头方向也随之翻转** |
| 卡片内「图标 + 文字」顺序 | ✅ 镜像 | 图标始终靠 start |
| 进度条 / 倒计时环填充方向 | ✅ 镜像 | 顺/逆时针由方向决定 |
| 侧滑面板滑入侧 | ✅ 镜像 | 从 end 侧滑入 |
| 列表项指示箭头 | ✅ 镜像 | 指向 end |
| **阿拉伯数字（0–9）** | ❌ **不镜像** | 保持 LTR 排布，数值不得翻转 |
| **倒计时数字** | ❌ **不镜像** | 同上；但**容器位置**镜像 |
| **网格类棋盘 / 棋盘本体** | ❌ **不镜像** | 见下方理由 |
| 品牌 logo / 主视觉插画 | ❌ 不镜像 | 翻转会导致画面里的人物、文字反向 |
| 书法类装饰纹样 | ❌ 不镜像 | 书法有方向性，翻转即错 |
| 物品 / 角色插画图标 | ❌ 不镜像 | 轴侧或固定透视的插画翻转会破坏统一性 |

> **棋盘不镜像的理由（可直接引用）**：棋盘是**空间**不是文本，网格通常左右对称，镜像零收益；反而会让「同一条合成链在两个语言版本里位置不同」，引发存档、录屏素材、玩家攻略的版本分裂。**全案保持同一张棋盘。**

## 五、文案与文化（RTL 专属）

| 项 | 规范 |
| --- | --- |
| 翻译来源 | **禁止机翻直出**，必须母语者过审 |
| 用词 | 避免方言差异（Gulf / Levantine / Egyptian 差别大），用现代标准阿拉伯语（MSA） |
| 借贷词 | 直接用英文 loanword 能懂但廉价感强；物品名优先本地传统名词 |
| 数字混排 | 阿语文本中的数字与拉丁词保持 LTR 嵌入（bidi），不得强制整体 RTL |

## 六、合规红线**不绑定语言**（最容易误删的一节）

用户把语言范围收缩为「只做英文」时，**不要把合规节一起删掉**：

- 文化/宗教/形象类红线由**目标市场**决定，不由界面语言决定 —— 英文界面投中东市场，照样会被同一套审核下架。
- 做法：把这些条目**单独拆成一节**，注明「与语言无关，本版仍适用」，与语言相关的内容（镜像、字体、补偿系数）分开存放。

常见红线维度（按市场配置）：女性形象表现、宗教符号与节日视觉、手势与左右手、酒与赌博元素、国旗政治符号、文案用词。

## 七、存档格式（本版不实施时怎么写）

把完整推演压进附录，不要删：

```
## 附录 X：<语言/特性> 支持（暂缓，本版不实施）

> **状态**：存档待启。[已决策 YYYY-MM-DD] 本版只做 <当前范围>，本节内容不进入本版开发范围。
> **启用条件**：<什么情况下启用>
> **保留原因**：<为什么值得留着>
```

同时在正文对应位置留一行指向附录（如「阿拉伯语 RTL → 暂缓，方案见附录 A」），并在最终自检表里加一行「RTL 完整方案已存档」。
