# STE100 既有文档集改造（retrofit）

## When to Use（触发条件）

用户说「按 STE100 / asd-ste100 原则**审核并优化**某套文档」「这套文档过一遍 STE100」。关键词是**既有**文档 —— 已经成型、有交叉引用、有版本表、可能还有代码与出图提示词混在里面。

**和 `ste-writing-standard` 的分工**：那个 skill 管「**写新文档**时用多严的 STE（80%–100% 分档）」。本 skill 管「**既有文档集怎么安全地批量改**」。两者的规则本体都在 `asd-ste100`，不要在这里重复。

**核心风险模型与写新文档相反**：写新文档怕写得不好；改既有文档怕**改坏**（静默丢内容、切碎数值、误伤功能性描述）。所以第一原则是 **先审后改、改完验零丢失**。

## 流程

### 1. 先审计，别先改

全量扫描 → 输出量化报告（每份文档的违规计数 + 按风险排序的清单）→ **让用户拍板执行范围与批次**。

报告至少要有：总量统计 · 逐文档计分表 · 每类违规的**真实 before/after 示例** · 建议批次 · 需拍板的开放问题（编号，便于用户批量回复）。

**未经确认不要批量重写。** 本工作区的规矩是逐份交付、逐批确认；一次性重写 30 份文档会直接踩这条线。

### 2. 分类统计前先分母

同一个「；」在不同位置含义完全不同，统计和处理必须分开：

| 位置 | 处理 |
| --- | --- |
| 散文（规则 / 文案 / 论述） | STE 8.1 硬禁，必须处理 |
| 表格单元格 | 多为参数分隔 → 本工作区规矩是**改 `<br>`（换行）** |
| 代码围栏内 / 行内 `` ` `` 内 | **不动**。可能是字面量（如速查表里的 `` `.!?；` ``） |
| **图像生成提示词块** | **整体豁免**，见下节 |

统计口径要写进脚本，否则「全文 480 个分号」这种数字会把表格和代码里的都算进来，虚高一个数量级。

### 3. 机械替换优先，手改补位

**能脚本批量做**：`；`→`。`（散文）、`；`→`<br>`（表格）、营销形容词删除。

**必须手改**：
- **超长句**（中文 >40 字）：拆成 2+ 句，或按分号/破折号切分点断开
- **行内压缩规格**：形如 `- **模块 X** — 内容A、内容B / **作用**：①…；②…；③…` 的单行长条目。重排为：
  ```
  - **模块 X · 名称（阶段）**
    - **内容**：内容A、内容B
    - **作用**：
      - ① …
      - ② …
  ```
  **内容一字不减，只换结构。** 这类行的重排是脚本化的：`ste_scan_cn.py --module-cards FILE` 先列出，`--restructure-module-cards FILE` 就地应用（幂等）。语义判断仍留给人。

### 4. 逐行定点替换，不要整篇重写

构造 `{行号: 新文本}` 交给脚本应用；**未命中的行保持逐字不变**。整篇重新生成既有文档会静默丢内容，且事后无法核对。

替换按**行号倒序**应用；若某行替换成多行（子列表），正序会让后面所有行号错位。

### 5. 改完必须验零丢失

取 `git show HEAD:<path>` 与新版做 **token 多重集 diff**：去标点后按「CJK 串 / 英文串 / 数字」分组计数，比较两侧的多重集差。

差异必须**全部可解释**为本次改写（删了「彻底」、加了「内容/作用」标签、句子重切导致 token 边界重排）。任何无法解释的减少 = 内容丢了，回查。

不要靠肉眼，也不要只比字符数。

### 6. 每份改动过的文档加修改记录

用户会明确要求「记得加入修改记录」。做法：

- 有 `## 版本记录` 表的 → 表内追加一行，版本号 **+0.1**，日期用当天
- 统一条目文案：`STE100 结构规范化：清除分号、拆分超长句、表格内分号改 <br>。内容与数值未变。`
- **无版本表的文件**（拆分副本、INDEX 之类）→ 在索引文件里记一行，说明批次范围与豁免项

## 图像生成提示词块必须豁免

出图描述（**中英都算**）不能套 STE：

- 逗号长句是出图提示词的惯用语法，模型对此训练充分；拆句不提升出图质量
- 块内的 `呆萌 / 治愈系 / 圆润可爱 / cozy` 是**功能性风格词**，删掉会直接改变出图结果。STE 的词法规则会把它们当营销形容词清除，这是**误伤**
- **做法**：只审提示词块**之外**的说明段（画布 / 结构 / 状态差异 / 元素规格），块本身一字不动
- **识别特征**：`>` 引用块，且含色值 `#RRGGBB` / `px` / `×` / 「扁平风格」/「无 3D」

同理，这套豁免逻辑适用于任何「描述要喂给另一个模型」的文本（出图、TTS、翻译 prompt）。

## Pitfalls

| 坑 | 后果 | 避法 |
| --- | --- | --- |
| **先改后审** | 用户的范围意图没确认就动 30 份文档，返工且破坏信任 | 先出审计报告，等拍板再改 |
| **`；`→`。` 切断括号内句子** | `（甲；乙）` 变成 `（甲。乙）`，中文里很生硬 | 括号内的分号改 **`·`** 或 `，`；替换后专扫一遍 `（[^（）]*。` |
| **给提示词块套 STE** | 出图风格词被当营销词删掉，出图结果变差 | 提示词块整体豁免 |
| **整篇重写既有文档** | 内容静默丢失且无法核对 | 逐行定点替换 + token 多重集 diff |
| **统计不分母** | 表格/代码里的分号被算成散文违规，数字虚高 | 统计脚本按位置分类 |
| **按行号正序应用多行替换** | 多行替换顶掉后面所有行号 | **倒序**应用，或每批重新扫描 |
| **中文路径下直接用 git 输出** | 路径被八进制转义（`\346\260\264...`），脚本匹配不上 | 加 `-c core.quotepath=false` |
| **把分级档位名当营销词删** | 「完美」可能是 Perfect 四档之一的技术术语 | 删之前先看上下文；术语表里的词不动 |
| **把 `——` 当句末** | 用「——」串起的超长句会被反复判违规，容易陷入「放宽检测」的死循环 | `——` **不算句边界**。正解是**在 `——` 处拆句**，不是把检测放宽 |
| **改完不留痕** | 用户要求「记得加入修改记录」时会返工 | 第 6 步和改写同步做，别等被提醒 |
| **只报改了什么** | 营销形容词、英文 linter 项等**独立词法项**不在分号/长句的扫描口径里，用户容易以为已全清 | 交付时**主动列出「本次未覆盖的检查项」** |
| **扫描范围外还有文档** | 只有 `系统设计/` 在范围内时，同级 `README.md` 之类仍会带违规 | 交付前用脚本扫一次**上一级目录**，把范围外残留一并列出 |

## 验证

改完对每个文件跑一次收尾自检，四项全 0 才算完：

```bash
python3 <skill_dir>/scripts/ste_scan_cn.py <目录或文件> --exempt-prompt --json --baseline 0
```

- 散文分号 = 0 · 表格内分号 = 0 · 超长句 = 0 · 营销形容词 = 0
- 括号内句号 = 0
- 提示词块**计数为豁免**，不计入也不修改

零丢失验证（第 5 步）：

```bash
git show HEAD:<path> > /tmp/old.md
python3 <skill_dir>/scripts/ste_scan_cn.py --loss-check /tmp/old.md <path>
```

两者都过了才交付。

## 支持文件

- `scripts/ste_scan_cn.py` —— stdlib-only 自检器。三种模式：扫描（`--json` / `--baseline` / `--disable`）、模块卡片重排（`--module-cards` / `--restructure-module-cards`）、零丢失校验（`--loss-check OLD NEW`）。可直接复跑做交付前校验。
- `references/case-capyvoice-ste-retrofit.md` —— 一次完整实战（32 份 md / 400 KB / 六批跑完）的规模数字、分批方式、模块卡片重排正则、token 保真度校验片段与三个真实踩到的坑。**开工前扫一眼可标定工作量。**
